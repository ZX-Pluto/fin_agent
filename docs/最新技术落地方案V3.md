## 1. 产品定位与目标

**一句话定位**

AI 驱动的经营材料预审、经营洞察、知识沉淀与事项闭环管理平台，替代原区域承担的“审核、分析、归纳、跟踪”四项能力。

**核心业务问题**

区域取消后，机关直接面对 60+ 代表处，需要由 AI 补位完成：

| 原区域职责 | AI 对应能力 | 产品落点 |
| ---------- | ----------- | -------- |
| 检查材料有没有问题 | 完整性、一致性检查 | AI 预审中心 |
| 看数据真的假的 | 可信性、合理性校验 | AI 预审中心 |
| 总结观点 | 摘要、评分、画像、共性分析 | 经营洞察中心 |
| 持续跟踪 | 事项抽取、跨期匹配、提醒升级 | 事项闭环中心 |

**北极星指标**

- 材料自动化处理率 100%
- 会前审阅时间下降 ≥70%
- 重大问题会前发现率 ≥90%
- 事项按期闭环率提升 ≥30%
- Copilot 问答事实准确率 ≥95%，且必须带来源

## 2. 总体架构

### 2.1 分层结构

```text
展示层  Web 应用：材料 / 审核 / 洞察 / 知识 / 事项 / Copilot
业务层  材料服务 · 审核服务 · 洞察服务 · 知识服务 · 事项服务
AI 层   AI Review → AI Analyst → AI Copilot
        双通道解析 + Match + 事实源 + 主题模型 + 规则包分析
数据层  事实源 / 主题模型数据 / 经营卡片 / 指标库 / 事项库 / 向量库
接入层  上传 / URL / 定时同步 / OA·网盘·邮件对接
```

### 2.2 架构约束

1. **事实源是唯一可信数据源**：后续校验、洞察、问答、事项只消费事实源，禁止再次解析 PPT
2. **双通道解析**：组件解析与多模态解析都必须输出固定结构 JSON，经 Match 合并后进入事实源
3. **确定性优先**：复算、单位归一、跨页比对等逻辑用程序计算，LLM 只做理解类工作
4. **AI 能力全部 Skill 化**：沿用 Spring AI Alibaba 技能机制，Prompt 不写入 Java 业务代码
5. **Pipeline 而非 Chat**：解析与分析是固定流水线，Stage 之间不允许自由调用 LLM
6. **全链路可观测**：每个 Stage 记录起止时间、耗时、输入/输出摘要和错误，生成 Workflow Trace
7. **人工闭环**：AI 产出的问题、事项、评分默认是“建议”，人工确认或纠错后生效
8. **可替换**：OCR、视觉模型、渲染器、LLM 全部接口化

### 2.3 端到端主流程

```text
代表处提交材料（上传 / URL / 定时同步）
  ↓
材料入库
  ↓
双通道解析
├── 组件解析（POI + LLM）→ 组件 JSON
└── 多模态解析（OCR + Vision）→ 多模态 JSON
  ↓
Match / 查缺补漏（差异过大 → 重新解析）
  ↓
统一中间结果 JSON
  ↓
事实源抽取（固定可落库结构）
  ↓
主题模型落库（主题 → 一级指标 → 二级指标）
  ↓
选择规则包 / 主题 → AI 分析
  ↓
分析结论（问题 / 证据 / 建议 / 置信度）
  ↓
五大中心消费
AI 预审中心 → 经营洞察中心 → 事项闭环中心 → 经营知识中心 + AI Copilot
```

## 3. 功能范围

### 3.1 材料中心

- 材料来源：手工上传（PPT / PDF / Word）、URL 采集、定时同步
- 材料状态机：`待处理 → 解析中 → 匹配校验中 → 分析中 → 已完成 / 存在问题 / 解析失败`
- 批量导入 60+ 份材料并并发解析
- 材料列表与详情：状态、可信度、问题数、双通道解析记录、Workflow Trace、IR/事实源预览、重试入口

### 3.2 AI 预审中心

按领导思维分为四个 Tab：

| Tab | 检查重点 |
| --- | -------- |
| 完整性 | 漏页、漏章节、缺附件、缺指标 |
| 可信性 | 同比/环比复算、增长率一致、引用一致、外围数据一致 |
| 合理性 | 异常波动、行业规律、矛盾、风险信号 |
| 一致性 | 单页、跨页、跨 PPT、跨期间、跨代表处 |

每条问题包含等级、证据（页码 + 原文引用）、建议、规则 ID、事实源 ID、人工确认状态。

### 3.3 经营洞察中心

- 经营雷达：本期材料数、重大问题数、中风险数、建议关注数
- Top 异常指标自动识别
- 代表处评分与排行切片
- 共性主题聚类
- 跨周期对比与趋势联动

### 3.4 经营知识中心

- 经营卡片：每代表处 × 每周期一张
- 指标库：统一指标名称、别名、单位、口径
- 历史材料自动沉淀，支持跨年度检索与对比
- 知识问答：基于卡片库 + 向量检索，回答必须带来源

### 3.5 事项闭环中心

- 事项抽取：事项、责任人、截止时间、来源页码
- 人工确认后才进入事项池
- 跨期匹配：同一代表处 + 事项文本相似度 ≥0.85 + 责任人一致
- 状态机：`待办 → 进行中 → 已完成 / 逾期 / 取消`
- 提醒升级：截止前 7 天提醒，逾期自动升级，连续 3 期未完成红牌预警

### 3.6 新增：主题模型与规则包

- 主题模型：主题 → 一级指标 → 二级指标，含表结构、口径、公式、注释
- 规则包：规则包 → 规则条目，规则条目可被多个规则包引用
- 分析任务：选择规则包 / 主题后执行材料分析，输出分析结论

## 4. 核心数据流与 AI 能力

### 4.1 双通道解析

| 通道 | 输入 | 实现 | 输出 |
| ---- | ---- | ---- | ---- |
| 组件解析 | PPT/Word/Excel 原生结构 | POI 提取 + LLM 结构化 | 组件 JSON |
| 多模态解析 | 页面渲染图 | OCR + 视觉模型 | 多模态 JSON |

两个通道输出同一固定 JSON Schema：`slideNo / title / texts / tables / charts / images / metrics / confidence / rawRef`。

### 4.2 Match 与查缺补漏

- 按 `slideNo` 对齐
- 查缺补漏：合并两通道独有字段，保留置信度高的一侧
- 数值对齐：同一指标做单位归一与数值比对
- 冲突标记：无法对齐字段标记 `CONFLICT`

差异评分公式：

```text
差异分 = 0.40 × 字段缺失率
       + 0.30 × 数值不一致率
       + 0.20 × 语义不一致率
       + 0.10 × (1 - min(confA, confB))
```

可接受阈值：

| 等级 | 条件 | 处理 |
| ---- | ---- | ---- |
| 接受 | 差异分 < 0.10 且字段完整率 ≥95% | 直接合并 |
| 需复核 | 0.10 ≤ 差异分 < 0.30 | 合并并标记待人工复核 |
| 重新解析 | 差异分 ≥0.30 或字段完整率 <95% | 触发重新解析 |
| 关键冲突 | 关键指标相对偏差 >0.5% | 标记冲突并生成预审问题 |

### 4.3 事实源

中间结果必须抽取为固定可落库的事实源：

```json
{
  "factId": "F-2026Q2-BJ-0001",
  "materialId": "MAT-2026Q2-BJ-01",
  "factType": "METRIC",
  "subject": {"id": "SUB-02-01", "name": "营业收入", "level": "二级指标"},
  "period": "2026Q2",
  "value": 1000,
  "unit": "万元",
  "source": {"slideNo": 8, "blockId": "B12", "quote": "营业收入 1000万元"},
  "confidence": 0.96,
  "channel": "MERGED",
  "status": "DRAFT"
}
```

事实源类型：`METRIC / EVENT / RISK / HIGHLIGHT / ACTION / FORECAST / TEXT / CHART`。

### 4.4 主题模型

```text
主题模型
├── 盈利能力
│   ├── 收入（一级）
│   │   ├── 营业收入（二级）
│   │   └── 其他业务收入（二级）
│   ├── 利润（一级）
│   └── 费用（一级）
├── 营运能力
├── 现金流
└── 风险合规
```

模型节点包含：编码、名称、别名、主题、上级指标、级别、单位、公式、校验规则、注释。

表结构示例：

```sql
CREATE TABLE ai_subject_model (
    id          BIGSERIAL PRIMARY KEY,
    code        VARCHAR(64) NOT NULL,
    name        VARCHAR(128) NOT NULL,
    alias       TEXT,
    theme       VARCHAR(64),
    parent_id   BIGINT,
    level       VARCHAR(16) NOT NULL,
    unit        VARCHAR(32),
    formula     TEXT,
    comment     TEXT,
    create_time TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE ai_model_data (
    id          BIGSERIAL PRIMARY KEY,
    model_id    BIGINT NOT NULL,
    material_id BIGINT NOT NULL,
    period      VARCHAR(32),
    fact_id     BIGINT,
    value       NUMERIC(20,4),
    unit        VARCHAR(32),
    confidence  NUMERIC(5,4),
    source_refs TEXT,
    create_time TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

中间结果按主题模型字段映射落库；未匹配字段进入“待映射 / 待确认”。

### 4.5 规则包与 AI 分析

```text
规则包
└── 规则条目（编码 / 名称 / 类别 / 等级 / 阈值 / 启停 / 适用范围）
```

分析输入：

```text
1. PPT 解析 JSON（双通道合并结果）
2. model->data（主题模型事实源）
3. 规则库（规则包 → 规则条目）
```

分析输出：

```json
{
  "conclusionId": "C-001",
  "materialId": "MAT-2026Q2-BJ-01",
  "theme": "盈利能力",
  "verdict": "NORMAL | ABNORMAL | NEED_CONFIRM",
  "findings": [
    {
      "severity": "HIGH",
      "message": "收入数据跨页不一致",
      "evidence": ["第5页 1000万元", "第12页 1200万元"],
      "factIds": ["F-001", "F-002"],
      "ruleId": "R-S02",
      "suggestion": "核对口径与原始数据"
    }
  ],
  "summary": "整体材料质量良好，但存在 2 项需要确认的数据一致性问题。",
  "confidence": 0.9
}
```

### 4.6 经营评分模型

```text
综合评分 = 财务表现分 × 60% + 材料质量分 × 20% + (100 - 风险暴露分) × 20%
```

- 评分必须输出评分说明和数据来源页
- 评分只用于排序与关注分级，不替代人工判断
- 权重与阈值后台可配置

## 5. 数据与存储

### 5.1 领域对象

```text
orgs / periods / materials / slides / blocks
fact_sources / subject_models / model_data
metrics / findings / action_items / cards / knowledge
rule_packages / rule_items / analysis_conclusions
task_runs / confirmations / audit_logs
```

### 5.2 存储设计

| 存储 | 用途 |
| ---- | ---- |
| PostgreSQL 15+ | 材料、事实源、主题模型、模型数据、卡片、事项、结论、确认等结构化数据 |
| pgvector | 卡片、事项、共性主题向量检索 |
| Redis + Redisson | 解析任务队列、状态缓存、会话 / Agent Checkpoint |
| MinIO / S3 | 原始文件、页图、导出文件 |
| 审计日志 | 操作留痕 |

所有 AI 输出落库前必须通过 Java Bean Validation + JSON Schema 校验，非法输出自动重试一次并记录。

## 9. 关键风险与对策

| 风险 | 对策 |
| ---- | ---- |
| 双通道解析差异大 | 差异评分 + 阈值配置，差异过大自动重解析，保留双通道原文 |
| PPT 版式多样导致解析不稳定 | 确定性提取 + 视觉理解分级，低置信度转人工 |
| LLM 幻觉导致误报 | 校验规则优先，LLM 只做理解，所有结论带证据，人工确认闭环 |
| 指标口径不统一 | 主题模型统一指标树、单位归一、公式与注释 |
| 中间结果无法映射模型 | 事实源 + 待映射/待确认队列，人工确认后回流 |
| 事项抽取噪声 | 人工确认后才入库，相似度匹配设阈值 |
| 经营数据敏感 | 私有化部署、数据不出域、RBAC 权限、操作审计 |
| 多模态解析成本高 | 模型路由、结果缓存、批量并发复用 |

## 10. 验收标准

1. 全流程跑通：材料 → 双通道解析 → Match → 事实源 → 主题模型落库 → 规则包分析 → 五大中心
2. 双通道差异阈值可配置，差异过大可触发重新解析
3. 事实源字段完整率 100%，通过 Bean Validation / JSON Schema 校验
4. 所有 AI 输出可溯源到事实源、材料与页码
5. 每个解析任务有完整 Workflow Trace
6. 问题与事项支持人工确认 / 纠错，纠错结果可回流
