## 1. 产品定位与目标

**一句话定位**

AI 驱动的经营材料预审、经营洞察、知识沉淀与事项闭环管理平台，替代原区域承担的“审核、分析、归纳、跟踪”四项能力。

**核心业务问题**

区域取消后，机关直接面对 60+ 代表处，需要由 AI 补位完成：

| 原区域职责       | AI 对应能力                | 产品落点     |
| ---------------- | -------------------------- | ------------ |
| 检查材料有没有问题 | 完整性、一致性检查         | AI 预审中心  |
| 看数据真的假的     | 可信性、合理性校验         | AI 预审中心  |
| 总结观点           | 摘要、评分、画像、共性分析 | 经营洞察中心 |
| 持续跟踪           | 事项抽取、跨期匹配、提醒升级 | 事项闭环中心 |

**北极星指标**

- 材料自动化处理率 100%；
- 会前审阅时间下降 ≥70%；
- 重大问题会前发现率 ≥90%；
- 事项按期闭环率提升 ≥30%；
- Copilot 问答事实准确率 ≥95%，且必须带来源。

## 2. 总体架构

### 2.1 分层结构

```text
展示层  Web 应用：材料 / 审核 / 洞察 / 知识 / 事项 / Copilot
业务层  材料服务 · 审核服务 · 洞察服务 · 知识服务 · 事项服务
AI 层   AI Review → AI Analyst → AI Copilot
        解析流水线 + 规则引擎 + Skill
数据层  Business IR / 经营卡片 / 指标库 / 事项库 / 向量库
接入层  上传 / URL / 定时同步 / OA·网盘·邮件对接
```

### 2.2 架构约束

1. **Business IR 是唯一可信数据源**：后续 Validation、Knowledge、QA 等模块只消费 IR，禁止再次解析 PPT。
2. **确定性优先**：能用规则和代码计算的逻辑（同比复算、单位归一、跨页比对）不使用 LLM；LLM 只做理解类工作。
3. **AI 能力全部 Skill 化**：沿用现有 Spring AI Alibaba 技能机制（`resources/commonSkills` + 按需技能 + `CompositeSkillsInterceptor`），Skill 定义与 Prompt 独立维护，不写入 Java 业务代码。
4. **Pipeline 而非 Chat**：解析是固定流水线，Stage 之间不允许自由调用 LLM。
5. **全链路可观测**：每个 Stage 记录起止时间、耗时、输入/输出摘要和错误，统一生成 Workflow Trace。
6. **人工闭环**：AI 产出的问题、事项、评分默认是“建议”，人工确认或纠错后生效，纠错结果回流到规则与提示词。
7. **可替换**：OCR、视觉模型、渲染器、LLM 全部接口化，业务代码不依赖具体实现。

### 2.3 端到端主流程

```text
代表处提交材料（上传 / URL / 定时同步）
  ↓
材料入库 → 解析流水线（读取→解析→渲染→OCR→视觉→业务理解→IR）
  ↓
Business IR（指标 / 问题 / 事项 / 摘要 / 置信度）
  ↓
AI 预审中心：完整性 · 可信性 · 合理性 · 一致性 → 问题清单
  ↓
经营洞察中心：评分 / 排行 / 雷达 / 共性聚类 → 经营卡片
  ↓
事项闭环中心：抽取 → 确认 → 跨期匹配 → 跟踪提醒
  ↓
经营知识中心 + AI Copilot：沉淀 · 检索 · 问答
```

## 3. 功能范围

### 3.1 材料中心

- 材料来源：手工上传（PPT / PDF / Word）、URL 采集、定时同步；
- 材料状态机：`待处理 → 解析中 → AI 审核中 → 已完成 / 存在问题 / 解析失败`；
- 批量导入 60+ 份材料并并发解析；
- 材料列表与详情：状态、可信度、问题数、Workflow Trace、阶段日志、IR 预览、重试入口。

### 3.2 AI 预审中心

按领导思维分为四个 Tab：

| Tab      | 检查重点                                       |
| -------- | ---------------------------------------------- |
| 完整性   | 漏页、漏章节、缺附件、缺指标                   |
| 可信性   | 同比/环比复算、增长率一致、引用一致、外围数据一致 |
| 合理性   | 异常波动、行业规律、矛盾、风险信号             |
| 一致性   | 单页、跨页、跨 PPT、跨期间、跨代表处           |

每条问题包含等级、证据（页码 + 原文引用）、建议、规则 ID、人工确认状态。

### 3.3 经营洞察中心

- 经营雷达：本期材料数、重大问题数、中风险数、建议关注数；
- Top 异常指标自动识别；
- 代表处评分与排行切片；
- 共性主题聚类，如“多个代表处提及海外订单延期”；
- 跨周期对比与趋势联动。

### 3.4 经营知识中心

- 经营卡片：每代表处 × 每周期一张，统一沉淀评分、摘要、亮点、风险、事项、核心指标、可信度；
- 指标库：统一指标名称、别名、单位、口径；
- 历史材料自动沉淀，支持跨年度检索与对比；
- 知识问答：基于卡片库 + 向量检索，回答必须带来源。

### 3.5 事项闭环中心

- 事项抽取：事项、责任人、截止时间、来源页码；
- 人工确认后才进入事项池；
- 跨期匹配：同一代表处 + 事项文本相似度 ≥0.85 + 责任人一致；
- 状态机：`待办 → 进行中 → 已完成 / 逾期 / 取消`；
- 提醒升级：截止前 7 天提醒，逾期自动升级，连续 3 期未完成红牌预警。

## 4. AI 流水线与规则引擎

### 4.1 解析流水线

```text
Stage 1   File Loader      上传/URL → 本地文件          无 LLM
Stage 2   Document Parser  文件 → Document Tree         无 LLM
Stage 3   Page Renderer    文档 → 每页 PNG               无 LLM
Stage 4   OCR              图片 → 文字                  可替换
Stage 5   Vision           图表/SmartArt/流程图 → JSON   多模态模型
Stage 6   Business         页面分类 / 实体 / 指标 / 事项 / 问题
Stage 7   IR Builder       Merge + Normalize + Validate → Business IR
```

落地技术：Stage 1–3 由 Java 服务实现（Apache POI 解析、LibreOffice CLI 渲染），Stage 4 调 OCR 服务，Stage 5–6 通过 Spring AI 调多模态 / 文本模型，Stage 7 用 Java 确定性代码合并、归一化并校验。

平台层（阶段 1 起追加）：

```text
Stage 8   Review Engine    IR + 规则库 + 外围数据 → Findings
Stage 9   Insight Engine   评分 / 排行 / 雷达 / 共性聚类
Stage 10  Card Builder     IR + 洞察 → 经营卡片
Stage 11  Action Tracker   事项匹配历史、状态流转、提醒
```

### 4.2 Skill 规范

沿用 `efm-ai-agent-service` 的技能体系：`resources/commonSkills` 维护全局技能，按需技能按目录组织，由 `CompositeSkillsInterceptor` 动态匹配加载；每个 Skill 的职责、Prompt、输出结构独立维护，不写入 Java 业务代码。

```text
skills/
├── vision/                 # 图表、SmartArt、流程图理解
├── slide_classifier/       # 页面分类
├── entity_extractor/       # 指标、组织、人员、时间、问题
├── schema_extractor/       # Risk / Finding / Todo / Forecast
├── relationship_builder/   # 指标→原因→发现
├── finding_checker/        # 预审问题判定（LLM 兜底）
├── action_extractor/       # 事项、责任人、截止时间
└── qa/                     # Copilot 问答链路
```

### 4.3 预审规则库

全部可配置，覆盖四类规则：

| 类别   | 规则范围                                                     |
| ------ | ------------------------------------------------------------ |
| 完整性 | 必选章节、必填指标、期间标识、页数异常、附件缺失             |
| 可信性 | 同比/环比复算、增长率口径一致、引用一致、外围数据比对、单位归一 |
| 合理性 | 异常波动、行业规律、矛盾检测、风险信号、目标达成率           |
| 一致性 | 单页内、跨页、跨 PPT、跨期间、跨代表处                       |

### 4.4 经营评分模型

```text
综合评分 = 财务表现分 × 60% + 材料质量分 × 20% + (100 - 风险暴露分) × 20%
```

- 评分必须输出评分说明和数据来源页；
- 评分只用于排序与关注分级，不替代人工判断；
- 权重与阈值后台可配置。

## 5. 数据与存储

### 5.1 领域对象

```text
orgs / periods / materials / slides / blocks
metrics / findings / action_items / cards / knowledge
task_runs / confirmations / audit_logs
```

### 5.2 Business IR 要点

- `material`：材料标识、代表处、期间、来源类型、文件信息；
- `slides`：页面分类、标题、blocks、图片、OCR 文本、视觉描述、备注；
- `metrics`：指标名、别名、单位、值、同比、环比、目标、达成率、来源、置信度；
- `findings`：分类、等级、标题、证据、规则 ID、人工确认状态；
- `action_items`：事项、责任人、截止时间、状态、来源页码；
- `summary`：经营评分、亮点、风险、置信度。

所有 AI 输出落库前必须通过 Java Bean Validation + JSON Schema 校验（Fastjson2 反序列化后校验），非法输出自动重试一次并记录。

### 5.3 存储设计

| 存储                 | 用途                                             |
| -------------------- | ------------------------------------------------ |
| PostgreSQL 15+（驱动 42.7.2） | 材料、IR、卡片、事项、审核确认等结构化数据       |
| pgvector（待确认启用） | 卡片、事项、共性主题向量检索                     |
| Redis + Redisson     | 解析任务队列、状态缓存、会话 / Agent Checkpoint  |
| MinIO / S3           | 原始文件、页图、导出文件                         |
| 审计日志             | 操作留痕                                         |

### 6.3 与现有工程架构的衔接

沿用 `efm-ai-agent-service` 的分层与技能机制：

```text
facade（JAX-RS API）→ agent（Spring AI Agent / Skill）→ tool（@Tool）
→ service（业务服务）→ client（EFM / EDM / 数据仓库 / 即席查询等外部服务客户端）
```

- Skill 化沿用现有机制：`resources/commonSkills` 全局技能 + 按需技能目录 + `CompositeSkillsInterceptor` 动态匹配加载，Prompt 与技能定义不写入 Java 业务代码；
- 会话隔离沿用 ThreadLocal Session + Redis Agent Checkpoint + ExcelWorkbookManager 工作簿池；
- 材料解析、规则引擎等确定性 Stage 放 service 层；LLM 理解类能力放 agent / tool 层，统一走 Spring AI。

### 6.4 模型与部署要求

- 文本模型：Qwen-V3-32B，用于业务理解、校验、摘要、问答；
- 多模态视觉模型：用于图表、SmartArt、流程图理解（待确认 AI 网关模型清单）；
- API Key、额度、并发配额按 AI 网关既有规范申请；
- 正式环境建议内网 / 私有化部署模型，数据不出域；对外 HTTPS + 反向代理 + 审计日志。

## 9. 关键风险与对策

| 风险                 | 对策                                                   |
| -------------------- | ------------------------------------------------------ |
| PPT 版式多样导致解析不稳定 | 确定性提取 + 视觉理解分级，低置信度转人工            |
| LLM 幻觉导致误报     | 校验规则优先，LLM 只做理解，所有结论带证据，人工确认闭环 |
| 指标口径不统一       | 指标库统一口径、单位归一，跨代表处一致性提示           |
| 事项抽取噪声         | 人工确认后才入库，相似度匹配设阈值                     |
| 经营数据敏感         | 私有化部署、数据不出域、RBAC 权限、操作审计            |
| 多模态解析成本高     | 模型路由、结果缓存、批量并发复用                       |
| 技术栈能力缺口（视觉模型、OCR、PDF 解析、向量检索） | 主线选型按技术栈.md 冻结，缺口项在 M0 前评审补充并保持接口化 |

## 10. 验收标准

1. 全流程跑通：材料 → IR → 预审 → 卡片 → 洞察 → 事项 → 问答；
2. Business IR 字段完整率 100%，通过 Bean Validation / JSON Schema 校验；
3. 所有 AI 输出可溯源到具体材料与页码；
4. 每个解析任务有完整 Workflow Trace；
5. 问题与事项支持人工确认 / 纠错，纠错结果可回流。
