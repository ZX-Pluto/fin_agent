# AI 经营材料智能处理平台 — 重构方案 V2

版本：v2.0 ｜ 日期：2026-08-18 ｜ 状态：整理稿，待评审

## 0. 定位

V2 把原“解析流水线 + 规则校验”升级为：

```text
双通道解析 → Match/查缺补漏 → 事实源 → 主题模型 → 规则包分析 → 分析结论
```

核心原则不变：**LLM 负责理解，程序负责确定性处理；结论必须可溯源。**

## 1. 总体数据流

```text
代表处材料（PPT / PDF / Word / 图片）
        ↓
┌──────────────────────────────┐
│ 通道A：组件解析               │
│ POI 组件 + LLM 结构化         │
└──────────────┬───────────────┘
               │
               ▼
         固定结构 JSON（组件结果）
               │
┌──────────────┼──────────────┐
│ Match & 查缺补漏             │
│ 字段合并 / 数值对齐 / 置信度  │
│ 差异过大 → 触发重新解析       │
└──────────────┬──────────────┘
               ▼
         统一中间结果 JSON
               ↓
事实源抽取（固定可落库数据结构）
               ↓
主题模型落库（主题 → 一级指标 → 二级指标）
               ↓
选择规则包 / 主题 → AI 分析
               ↓
分析结论（问题 / 证据 / 建议 / 置信度）
```

## 2. 双通道解析

### 2.1 通道定义

| 通道 | 输入 | 实现 | 输出 |
| ---- | ---- | ---- | ---- |
| 通道A：组件解析 | PPT/Word/Excel 原生结构 | POI 提取文本/表格/形状 + LLM 结构化 | `ComponentParseResult` |
| 通道B：多模态解析 | 页面渲染图 | OCR + 视觉模型 | `MultimodalParseResult` |

两个通道必须输出**同一个固定 JSON Schema**：

```json
{
  "materialId": "MAT-2026Q2-BJ-01",
  "slides": [
    {
      "slideNo": 8,
      "title": "收入情况",
      "texts": ["营业收入 1000万元"],
      "tables": [["指标", "本期", "同比"]],
      "charts": [{"type": "bar", "data": {...}}],
      "images": [{"path": "...", "ocrText": "...", "visionDesc": "..."}],
      "metrics": [{"name": "营业收入", "value": 1000, "unit": "万元", "confidence": 0.96}],
      "confidence": 0.95,
      "rawRef": {"blockId": "B12", "quote": "营业收入 1000万元"}
    }
  ]
}
```

### 2.2 Match 与查缺补漏

按 `slideNo` 对齐两个通道，然后：

1. **查缺**：某字段 A 有 B 没有，保留置信度高的一侧并补全
2. **补漏**：合并两个通道独有的字段（例如 A 只有文本、B 识别出图表）
3. **对齐**：同一指标在两个通道的数值、单位、期间做比对
4. **标记**：无法对齐或冲突的字段标记 `CONFLICT`，进入人工复核

## 3. 差异评价与重解析

### 3.1 差异评分公式（建议）

```text
差异分 = 0.40 × 字段缺失率
       + 0.30 × 数值不一致率
       + 0.20 × 语义不一致率
       + 0.10 × (1 - min(confA, confB))
```

各子项定义：

| 子项 | 计算方式 |
| ---- | ---- |
| 字段缺失率 | 缺失必填字段数 ÷ 必填字段总数 |
| 数值不一致率 | 偏差超过阈值的指标对数 ÷ 两通道共识别指标对数 |
| 语义不一致率 | LLM 判定“矛盾/无法对齐”的 slide 数 ÷ slide 总数 |
| 置信度 | 两通道该页置信度的最小值 |

数值偏差定义：

```text
相对偏差 = |值A - 值B| ÷ max(|值A|, |值B|)
绝对偏差 = |值A - 值B|
```

### 3.2 可接受阈值（建议初始值，全部可配置）

| 等级 | 条件 | 处理 |
| ---- | ---- | ---- |
| 接受 | 差异分 < 0.10 且字段完整率 ≥ 95% | 直接合并，A 为主、B 补缺 |
| 需复核 | 0.10 ≤ 差异分 < 0.30 | 合并结果，标记“待人工复核”，保留双通道原文 |
| 重新解析 | 差异分 ≥ 0.30，或字段完整率 < 95% | 触发重解析：换模型 / 提高输出长度 / 局部重跑 / 启用视觉补强 |
| 关键冲突 | 关键指标相对偏差 > 0.5%（或绝对值超单位精度） | 标记冲突，并作为预审问题输出 |

阈值放在规则库/配置表中，支持按材料类型或主题覆盖。

## 4. 中间结果 → 事实源

合并后的中间结果不能直接用于分析，必须抽取为**固定可落库的事实源（FactSource）**。

```json
{
  "factId": "F-2026Q2-BJ-0001",
  "materialId": "MAT-2026Q2-BJ-01",
  "factType": "METRIC",
  "subject": {
    "id": "SUB-02-01",
    "name": "营业收入",
    "level": "二级指标"
  },
  "period": "2026Q2",
  "value": 1000,
  "unit": "万元",
  "source": {
    "slideNo": 8,
    "blockId": "B12",
    "quote": "营业收入 1000万元"
  },
  "confidence": 0.96,
  "channel": "MERGED",
  "status": "DRAFT",
  "rawJson": {}
}
```

事实源类型：

```text
METRIC     经营指标
EVENT      经营事件
RISK       经营风险
HIGHLIGHT  经营亮点
ACTION     整改/待办事项
FORECAST   预测/目标
TEXT       页面关键文本
CHART      图表数据
```

事实源是后续所有分析唯一消费的数据层，不再直接读原始解析 JSON 做判断。

## 5. 主题模型

### 5.1 模型定义

模型 = 主题 + 指标树 + 表结构 + 注释。

```text
主题模型
├── 盈利能力
│   ├── 收入
│   │   ├── 营业收入
│   │   └── 其他业务收入
│   ├── 利润
│   │   ├── 毛利润
│   │   ├── 净利润
│   │   └── 利润率
│   └── 费用
│       ├── 销售费用
│       └── 管理费用
├── 营运能力
│   ├── 库存
│   └── 应收
├── 现金流
│   └── 经营现金流
└── 风险合规
    ├── 风险信号
    └── 整改事项
```

每个节点包含：

```text
指标编码 / 指标名称 / 别名 / 所属主题 / 上级指标 / 级别 / 单位 / 口径 / 公式 / 校验规则 / 注释
```

### 5.2 表结构示例

```sql
-- 主题模型定义（表结构 + 注释）
CREATE TABLE ai_subject_model (
    id          BIGSERIAL PRIMARY KEY,
    code        VARCHAR(64) NOT NULL,          -- 指标编码
    name        VARCHAR(128) NOT NULL,         -- 指标名称
    alias       TEXT,                          -- 别名，如：营收 / 销售收入
    theme       VARCHAR(64),                   -- 所属主题
    parent_id   BIGINT,                        -- 上级指标
    level       VARCHAR(16) NOT NULL,          -- LEVEL1 / LEVEL2
    unit        VARCHAR(32),                   -- 标准单位
    formula     TEXT,                          -- 计算口径
    comment     TEXT,                          -- 注释
    create_time TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 模型落库数据
CREATE TABLE ai_model_data (
    id          BIGSERIAL PRIMARY KEY,
    model_id    BIGINT NOT NULL,               -- 关联主题模型节点
    material_id BIGINT NOT NULL,
    period      VARCHAR(32),
    fact_id     BIGINT,                        -- 关联事实源
    value       NUMERIC(20,4),
    unit        VARCHAR(32),
    confidence  NUMERIC(5,4),
    source_refs TEXT,                          -- 证据链 JSON
    create_time TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

### 5.3 中间结果落库

```text
事实源
  ↓ 按主题模型字段映射
ai_model_data
  ↓ 未匹配字段
待映射 / 待确认列表
```

落库时记录：来源 slide、block、原文、置信度、通道、事实源 ID。

## 6. 规则包与规则条目

```text
规则包（如：经营汇报预审包）
├── 规则条目 R-C01 必选章节
├── 规则条目 R-T01 同比复算
├── 规则条目 R-R01 异常波动
└── 规则条目 R-S02 跨页一致
```

- 规则包是分析任务的入口
- 规则条目包含：规则编码、名称、类别、等级、阈值参数、启停、适用范围
- 同一规则可被多个规则包引用

## 7. AI 分析

### 7.1 输入

```text
1. PPT 解析 JSON（双通道合并后的页面结构化结果）
2. model->data（主题模型中的事实源数据）
3. 规则库（规则包 → 规则条目 → 阈值）
```

### 7.2 流程

```text
选择规则包 / 主题
  ↓
加载对应模型指标与事实源
  ↓
确定性计算（复算、比较、阈值判断）
  ↓
LLM 语义分析（结合模型事实源 + PPT JSON）
  ↓
输出分析结论
```

### 7.3 分析结论结构

```json
{
  "conclusionId": "C-001",
  "materialId": "MAT-2026Q2-BJ-01",
  "theme": "盈利能力",
  "verdict": "NORMAL | ABNORMAL | NEED_CONFIRM",
  "findings": [
    {
      "severity": "HIGH",
      "message": "收入数据跨页不一致",
      "evidence": ["第5页 1000万元", "第12页 1200万元"],
      "factIds": ["F-001", "F-002"],
      "ruleId": "R-S02",
      "suggestion": "核对口径与原始数据"
    }
  ],
  "summary": "整体材料质量良好，但存在 2 项需要确认的数据一致性问题。",
  "confidence": 0.9
}
```

## 8. 可依赖的数据

| 数据 | 说明 | 用途 |
| ---- | ---- | ---- |
| PPT 解析 JSON | 双通道合并后的页面结构化结果 | 原文定位、证据、LLM 语义理解 |
| model->data | 主题模型中的事实源 | 指标口径统一、确定性计算、跨期/跨代表处比较 |
| 规则库 | 规则包 → 规则条目 | 阈值判断、预审规则执行 |

## 9. 与现有 MVP 的映射

| V2 概念 | 现有 MVP | 改动 |
| ------- | ------- | ---- |
| 组件解析 | POI 解析 + LLM 业务理解 | 输出固定 Schema |
| 多模态解析 | OCR/视觉留桩 | 补齐通道 |
| Match/查缺补漏 | 无 | 新增 |
| 事实源 | ai_business_metric / ai_knowledge | 抽象统一结构 |
| 主题模型 | 无 | 新增模型与落库 |
| 规则包分析 | ValidationTool + LLM 解释 | 升级为分析引擎 |

## 10. 实施建议

### Phase 0：解析层

- 定义统一 JSON Schema
- 双通道解析 + Match/查缺补漏
- 差异评分与阈值配置

### Phase 1：事实源层

- 事实源固定结构落库
- 中间结果 → 事实源抽取

### Phase 2：主题模型

- 模型定义与指标树
- 中间结果按模型落库
- 未匹配字段人工映射

### Phase 3：分析引擎

- 规则包/主题选择
- AI 结合 model->data + PPT JSON 分析
- 输出结论与证据链

## 11. 待确认事项

1. 差异阈值初始值是否需要按材料类型区分
2. 主题模型第一版覆盖哪些主题（建议：盈利能力、营运能力、现金流、风险合规）
3. 关键指标相对偏差 0.5% 是否合适，还是改用单位精度
4. 事实源是否需要版本化（同一材料多次解析结果对比）
