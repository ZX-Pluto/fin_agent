# AI 经营材料智能处理平台 — 最新技术落地方案 V4.4

版本：v4.6 ｜ 日期：2026-08-18 ｜ 状态：第一版开发基线版

## 0. 核心设计原则

```text
解析层负责“把材料变成事实”
模型层负责“把事实变成统一数据”
规则库负责“把专家经验结构化”
Agent 负责“基于事实和经验做判断”

规则不负责执行，AI 负责执行规则
模型不负责分析，模型负责提供结构化事实
```

## 1. 版本化与生命周期原则

### 1.1 四条技术原则

```text
原则一：失败不覆盖
  新版本处理失败时，不得影响当前有效版本

原则二：事实源不物理删除
  事实源版本化管理，失败/废弃版本保留，用于追溯与重新处理

原则三：模型数据与事实源建立版本关联
  每份模型数据记录来源事实源版本和模型版本，保证分析可追溯

原则四：只有完整链路成功才能成为 Current
  材料解析成功 → 事实源有效 → 模型映射成功 → 模型数据有效 → 分析成功 → 切换 Current
```

不要在“解析成功”时立即切换当前版本，应在对应阶段成功后切换对应的 current 指针。

### 1.2 版本链

```text
Material v1
  ↓
Fact Source v1
  ↓
Model v1
  ↓
Model Data v1
  ↓
Analysis Result v1
```

重新上传材料：

```text
Material v2 → Fact Source v2 → Model Data v2 → Analysis v2
```

只有完整成功的一条链可以成为当前版本。

### 1.3 版本保留策略

```text
业务有效版本：长期保留，不因版本策略自动删除
处理失败 / 中间版本：保留最近 N 个，超期归档
N 建议为 5，可配置
```

示例：

```text
北京代表处 / 2026-H1

Material V1  历史有效（长期保留）
Material V2  历史有效（长期保留）
Material V3  当前有效
Material V4  解析失败（自动清理候选）
Material V5  解析中（自动清理候选）
```

## 2. 术语定义

| 术语 | 定义 |
| ---- | ---- |
| PPT 解析 JSON | PPT 原文与视觉结构的解析结果，即原始材料证据 |
| 事实源 | 可用于业务判断的结构化材料事实 + 原始证据；第一版来源为 PPT 解析 JSON 按章节落库 |
| 主题 | 分析主题；包含 1 个模型 + 多个规则包 |
| 模型 | 一组结构化指标字段及其元数据；二维表是模型数据的呈现方式 |
| 模型数据 | 事实源映射到模型后的结构化数据 |
| 规则包 / 规则条目 | 分析知识资产，可动态创建 |
| 材料预审 | AI 基于事实源与预审核规则进行材料预审 |
| 经营分析 | AI 基于模型数据与专家经验规则进行分析 |
| Current 指针 | 当前有效版本指针：currentFactSourceId / currentModelDataId / currentAnalysisId |

## 3. 总体架构

### 3.1 主链路

```text
PPT / URL
  ↓
材料解析 Agent（Component + Vision + Match）
  ↓
PPT 解析 JSON
  ↓
事实源（按章节落库，代表处 + 期间维度，版本化）
  ↓
用户选择主题（1 个模型 + N 个规则包）
  ↓
┌─────────────────────┐
│ 材料预审 Agent       │   事实映射 Agent
│ 事实源 + 预审核规则  │   事实源 + 模型
│         ↓           │         ↓
│    预审结果          │     模型数据
└─────────┬───────────┘
          │
      分析前置检查（PASS / NEED_CONFIRM）
          │
          ▼
经营分析 Agent（模型数据 + 专家经验规则 + 数据查询工具）
  ↓
分析结论
  ↓
经营雷达 / Copilot / 五大中心
```

### 3.2 并行关系

```text
事实源
  ├→ 材料预审 Agent → 预审结果
  └→ 事实映射 Agent → 模型数据

预审 Agent 在必要时也可以查询模型数据
```

## 4. 材料解析与事实源

### 4.1 材料解析 Agent

```text
Component Parse（PPT 结构，无 LLM）
+ Vision Parse（OCR / 视觉）
→ Match
→ PPT 解析 JSON
```

### 4.2 事实源

事实源 = 结构化材料事实 + 原始证据，第一版来源为 PPT 解析 JSON 按章节落库：

```json
{
  "sourceId": "FS-001",
  "materialId": "MAT-001",
  "organization": "北京代表处",
  "period": "2026-H1",
  "chapter": "收入",
  "slideRange": [5, 8],
  "structuredFacts": [
    {"metric": "收入", "value": 756.7, "unit": "亿元", "growth": 26.4}
  ],
  "evidence": {
    "slide": 8,
    "blockId": "B12",
    "quote": "收入756.7亿元，同比增长26.4%"
  },
  "parseJson": {},
  "version": 1,
  "status": "ACTIVE",
  "createdTime": "2026-08-18T00:00:00"
}
```

未来事实源也可来自 Excel、系统数据、外部数据。

## 5. 版本状态设计

### 5.1 事实源状态

```text
PARSING        解析中
PARSED         解析成功，待质量校验
VALID          质量校验通过，可作为分析输入
WARNING        基本可用，存在非核心识别问题
PARSE_FAILED   技术解析失败
INVALID        无法作为后续 AI 分析的可靠输入
ACTIVE         当前有效事实源
SUPERSEDED     被新版本替代
```

### 5.2 模型数据状态

```text
MAPPING_FAILED  映射失败
ACTIVE          当前有效模型数据
SUPERSEDED      被新版本替代
```

### 5.3 失败处理

情况 A：技术解析失败

```text
PPT → 解析 → FAILED
当前事实源：保持旧版本
新事实源：PARSE_FAILED
模型数据：不变
```

情况 B：解析成功但质量不合格

```text
PPT 解析成功 → Match 成功 → 关键指标无法识别 → 质量校验失败
新事实源 = INVALID
不能覆盖当前 ACTIVE 事实源
```

情况 C：事实源成功但模型映射失败

```text
Fact Source v2 = PARSED
Model Data v2 = MAPPING_FAILED

Fact Source v1 = ACTIVE
Model Data v1 = ACTIVE
```

事实源与模型数据是两个独立生命周期，不要因映射失败删除事实源。

### 5.4 事实源质量判断

INVALID 不是“和原 PPT 100% 不一致”，而是“无法作为后续 AI 分析的可靠输入”：

| 情况 | 状态 |
| ---- | ---- |
| 普通文本少量识别失败 | VALID |
| 非核心图表识别失败 | VALID / WARNING |
| 核心收入指标无法识别 | INVALID |
| 组件解析与多模态解析局部差异 | VALID / WARNING |
| 核心数据存在重大冲突且无法消解 | INVALID |

质量判断采用“关键问题 + 完整性 + 解析置信度”综合判断，不做单一分数判定。

## 7. 模型与模型版本

### 7.1 模型定义

模型 = 一组结构化指标字段及其元数据：

```json
{
  "modelId": "M-001",
  "name": "经营情况模型",
  "version": 1,
  "fields": [
    {"code": "revenue", "name": "收入", "type": "number", "unit": "亿元", "comment": "经营收入"},
    {"code": "revenue_growth", "name": "收入同比", "type": "number", "unit": "%", "comment": "收入同比增长率"},
    {"code": "dso", "name": "DSO", "type": "number", "unit": "天", "comment": "回款天数"}
  ]
}
```

### 7.2 模型版本化与重映射

模型字段变化时，不要修改历史数据含义，按变更类型处理：

| 变更类型 | 策略 |
| ---- | ---- |
| 新增字段 | 增量映射，历史数据保留 |
| 修改字段名称 / 注释 | 通常无需重新解析事实源 |
| 修改字段类型 / 单位 / 语义 | 受影响字段重新映射 |
| 删除字段 | 新模型数据不再保留该字段 |

```text
Model v1 → Model Data v1（永远保留）
Model v2 → Model Data v2（重新生成）
```

历史分析结果始终可追溯。

## 10. Current 指针

显式记录当前有效版本，不使用 `max(version)`：

```text
北京代表处 / 2026-H1

currentFactSourceId = FS-002
currentModelDataId  = MD-002
currentAnalysisId   = AN-002
```

如果 FS-003 解析失败：

```text
currentFactSourceId 仍然 = FS-002
currentModelDataId  仍然 = MD-002
```

切换规则：

```text
材料解析成功 → 切换 fact source current
事实源有效 → 进入映射
模型映射成功 → 切换 model data current
分析成功 → 切换 analysis current
```

| 阶段 | 范围 | 主要验收 |

## 19. 验收标准

1. 全流程：上传 → 解析 → 事实源 → 主题 → 预审 + 模型映射 → 经营分析 → 结论
2. 事实源按代表处 + 期间 + 章节版本化落库
3. 新版本失败不影响当前有效版本
4. 事实源与模型数据独立生命周期，模型数据记录来源版本
5. 模型支持版本化与重新映射
6. Current 指针显式维护
7. AI 输出结构化结果，证据可溯源
