**能不能"直接上手"，取决于四类前置条件——部署环境、模型服务、平台配置、业务数据。Demo 阶段条件很少，正式上线阶段条件会明显变多。** 下面按档位拆开讲。

## 一、按使用档位看前置条件

| 档位         | 前置条件                                                   | 说明                          |
| ------------ | ---------------------------------------------------------- | ----------------------------- |
| 演示 Demo    | 一台可运行 Docker 的机器 + 一个模型 API Key + 几份测试 PPT | 单机即可跑通"上传→解析→卡片"  |
| 内部试用 MVP | 正式环境 + 组织主数据 + 指标口径库 + 10~20 份真实材料      | 材料中心、预审中心能真实验证  |
| 正式上线     | 全部平台配置 + 历史材料 + 外围数据 + 权限与合规 + 运维保障 | 才能支撑 60+ 代表处并形成闭环 |

## 二、系统/部署层前置条件（IT 侧）

这是"项目搭建后系统能跑起来"的基础：

- **运行环境**：Python 3.11、Node.js 18+；服务器需安装 LibreOffice（用于 PPT 转页图）、RapidOCR 的推理依赖。

- **基础设施**：PostgreSQL 15+（含 pgvector 扩展，用于向量检索）、Redis（任务队列）、MinIO/S3（原始文件和页图存储）。

- 模型服务

  ：一套 OpenAI Compatible 接口的模型，至少需要：

  - 文本模型（GPT / Claude / Qwen 任一，用于业务理解、校验、摘要、问答）；
  - 多模态视觉模型（用于图表、SmartArt、流程图理解）；
  - 对应的 API Key、额度、并发配额。

- **网络与安全**：经营数据敏感，正式环境建议私有化/内网部署模型，数据不出域；对外统一 HTTPS 入口并配反向代理、审计日志存储。

## 三、平台配置层前置条件（管理员/运营侧）

系统装好不等于能用，上线前必须把"业务字典"配好：

1. **组织主数据**：60+ 代表处的清单、层级归属、报送责任人；
2. **经营周期**：期间定义（如 2026Q2）、报送截止时间；
3. **指标口径库**：指标名称、别名、单位、口径（收入、利润、现金流、库存、费用等），这是跨代表处对比不失真的关键；
4. **模板与章节配置**：必选章节清单、材料模板（决定"完整性检查"的依据）；
5. **校验规则与阈值**：四类规则（完整性/可信性/合理性/一致性）的开关、阈值、等级配置；
6. **外围数据接入**：预算、财报、上期材料等，用于交叉校验与跨期对比；
7. **账号与角色**：机关领导 / 机关管理员 / 代表处三类角色，账号开通与权限分配；
8. **评分权重**：经营评分模型各因子权重确认。

## 四、用户使用层前置条件（最终用户侧）

对三类用户分别的要求：

- **机关领导**：账号开通；使用 Copilot 时了解"AI 结论必须带来源、可点进去核对页码"的边界；前 1~2 期需要参与结果复核。
- **机关管理人员**：熟悉问题清单确认/误报标记、事项确认与督办流程；负责首期校准——把 AI 误报人工纠正后，反馈回流到规则配置。
- **代表处**：按模板准备材料（标注期间、包含必填指标），在截止时间前通过上传 / URL / 定时同步提交。

其中最关键的一条使用习惯：**AI 产出（问题、事项、评分）默认是"建议"，必须人工确认后才生效**——这不只是流程要求，也是保证数据可信度、持续校准系统的机制。

## 五、上线前的"验收前置条件"

正式让用户使用前，建议先完成一轮质量基线测试：

- 用 10~20 份真实材料测试：解析成功率、指标抽取准确率、问题发现率；
- 校验规则误报率是否可接受（过高就调阈值）；
- 事项抽取→人工确认流程跑通；
- 数据备份与恢复演练完成。

一句话总结：**Demo 只要"机器 + 模型 Key + 测试 PPT"；真正让 60+ 代表处用起来，前置条件是"组织与指标主数据 + 历史材料 + 外围数据 + 模型合规部署 + 人工确认机制"这五件事。** 需要的话，我可以把这份前置条件整理成一份《上线前检查清单》（checklist），逐项打钩用。
