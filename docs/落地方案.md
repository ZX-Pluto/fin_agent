## 0. 文档定位

本文档承接两件事：产品概念（`docs/demo.md`）和 Material Parse Agent 工程规范（你之前贴的附件），目标是打通"概念 → 架构 → 实施"，形成一份可以直接进入开发的分阶段方案。

本方案按"平台"设计，但落地按"阶段"推进：先做能跑的 Demo，再做 MVP，最后形成完整平台。**解析能力只是地基，真正形成壁垒的是知识沉淀与事项闭环。**

## 1. 产品定位与目标

### 1.1 一句话定位

AI 驱动的经营材料预审、经营洞察、知识沉淀与事项闭环管理平台，替代原区域承担的"审核、分析、归纳、跟踪"四项能力。

### 1.2 核心业务问题

区域取消后，机关直接面对 60+ 代表处。原来区域负责人做的四件事现在必须由 AI 补位：

| 原区域职责         | AI 对应能力                  | 产品落点     |
| ------------------ | ---------------------------- | ------------ |
| 检查材料有没有问题 | 完整性、一致性检查           | AI 预审中心  |
| 看数据真的假的     | 可信性、合理性校验           | AI 预审中心  |
| 总结观点           | 摘要、评分、画像、共性分析   | 经营洞察中心 |
| 持续跟踪           | 事项抽取、跨期匹配、提醒升级 | 事项闭环中心 |

### 1.3 目标用户

| 角色         | 核心诉求                                             |
| ------------ | ---------------------------------------------------- |
| 机关领导     | 会前快速掌握全局问题，会后跟踪整改，随时自然语言问答 |
| 机关管理人员 | 材料收集、问题确认、事项督办、知识维护               |
| 代表处       | 报送材料、查看预审意见、反馈整改结果                 |

### 1.4 成功指标（北极星）

- 材料自动化处理率 100%：60+ 代表处材料全部自动解析、自动预审；
- 会前审阅时间下降 ≥70%；
- 重大问题会前发现率 ≥90%（以人工复核为准）；
- 事项按期闭环率提升 ≥30%；
- Copilot 问答事实准确率 ≥95%（人工抽检，必须带来源）。

## 2. 总体架构

### 2.1 分层架构

```
┌────────────────────────────────────────────────┐
│ 展示层   Web 应用：材料/审核/洞察/知识/事项 + Copilot │
├────────────────────────────────────────────────┤
│ 业务层   材料服务 审核服务 洞察服务 知识服务 事项服务 │
├────────────────────────────────────────────────┤
│ AI 层    AI Review → AI Analyst → AI Copilot     │
│          （解析流水线 + 规则引擎 + Skill）          │
├────────────────────────────────────────────────┤
│ 数据层   Business IR / 经营卡片 / 指标库 / 事项库 / 向量库 │
├────────────────────────────────────────────────┤
│ 接入层   上传 / URL / 定时同步 / OA·网盘·邮件对接     │
└────────────────────────────────────────────────┘
```

### 2.2 架构约束（必须遵守）

1. **Business IR 是唯一可信数据源**：后续 Validation / Knowledge / QA 等任何 Agent 禁止再次解析 PPT，只能消费 IR。
2. **确定性优先**：能用规则和代码算的（同比复算、单位归一、跨页比对）绝不让 LLM 算；LLM 只做"理解类"工作。
3. **AI 能力全部 Skill 化**：Prompt 不写进 Python 代码；每个 Skill 含 `skill.md`、`prompt.md`、`output_schema.json`。
4. **Pipeline 而非 Chat**：解析是固定流水线，Stage 之间禁止自由调用 LLM。
5. **全链路可观测**：每个 Stage 记录起止时间、耗时、输入/输出摘要、错误，统一生成 Workflow Trace。
6. **人工闭环**：AI 产出（问题、事项、评分）必须支持人工确认/纠错，纠错结果回流到规则与提示词。
7. **可替换**：OCR、视觉模型、渲染器、LLM 全部接口化，业务代码不依赖具体实现。

### 2.3 端到端主流程

```
代表处提交材料（上传 / URL / 定时同步）
  ↓
材料入库 → 解析流水线（读取→解析→渲染→OCR→视觉→业务理解→IR）
  ↓
Business IR（指标 / 问题 / 事项 / 摘要 / 置信度）
  ↓
AI 预审中心：完整性 · 可信性 · 合理性 · 一致性 → 问题清单
  ↓
经营洞察中心：评分 / 排行 / 雷达 / 共性聚类 → 经营卡片
  ↓
事项闭环中心：抽取 → 确认 → 跨期匹配 → 跟踪提醒
  ↓
经营知识中心 + AI Copilot：沉淀 · 检索 · 问答
```

## 3. 五大中心功能设计

### 3.1 材料中心

**功能清单**

- 材料来源：手工上传（PPT/PDF/Word）、URL 采集、定时同步（OA/网盘/邮件）；
- 材料状态机：`待处理 → 解析中 → AI 审核中 → 已完成 / 存在问题 / 解析失败`；
- 批量导入：支持一次导入 60+ 份材料并并发解析；
- 材料列表：代表处 × 周期 × 状态 × 可信度 × 问题数（类 GitHub Actions 体验）；
- 材料详情：解析进度、Workflow Trace、各阶段日志、IR 预览、重试入口。

**页面示意**

```
北京代表处 · 2026Q2经营汇报.ppt

AI状态        ★★★★★   可信度 92%   问题 5 个   [查看详情]
解析流水线     ✔ 读取  ✔ 解析  ✔ OCR  ✔ 视觉  ✔ 业务理解  ⏳ IR构建
```

### 3.2 AI 预审中心（重点）

按领导思维分四个 Tab，而不是按技术分类：

| Tab      | 检查什么                                          | 示例规则                                |
| -------- | ------------------------------------------------- | --------------------------------------- |
| ① 完整性 | 漏页、漏章节、缺附件、缺指标                      | 必选章节缺失、必填指标缺失、页数异常    |
| ② 可信性 | 同比/环比复算、增长率一致、引用一致、外围数据一致 | 数值与声称增速不符、单位不一致          |
| ③ 合理性 | 异常波动、行业规律、矛盾、风险信号                | 环比超 30% 无解释、文字说增长但数据下降 |
| ④ 一致性 | 单页、跨页、跨 PPT、跨期间、跨代表处              | 同一指标不同页数值不同                  |

**问题对象**：每条问题包含等级（重大/高/中/低）、证据（页码 + 原文引用）、建议、规则 ID、人工确认状态（待确认/误报/已确认）。

**页面示意**

```
AI审核 · 北京代表处 · 2026Q2        [完整性][可信性][合理性][一致性]

┌ 重大 利润同比口径不一致
│ 证据：第12页"利润118亿，同比+8.6%"；第5页上年同期102亿，实算+15.7%
│ 建议：核对口径（是否扣非/是否含汇兑）
└ [确认] [误报]
```

### 3.3 经营洞察中心

**功能清单**

- **经营雷达**：本期汇总（材料 68 份、重大问题 8、中风险 17、建议关注 26）；
- **Top 异常指标**：利润下降、现金流不足、库存上升、费用异常等自动识别；
- **代表处排行**：AI 自动评分，支持利润增长 TOP10 / 下降 TOP10 / 库存最高 / 收入最低等切片；
- **共性主题聚类**：如"18 个代表处都提到海外订单延期"，自动建议"机关统一制定专项方案"；
- **跨周期对比**：同一代表处多期趋势、同比环比联动。

**页面示意**

```
经营雷达 · 2026Q2
────────────────
材料 68 份    重大问题 8    中风险 17    建议关注 26
────────────────
Top 异常指标         代表处排行
 利润下降 ↓12%       北京 82  ★★★★★
 现金流紧张 6家       上海 78  ★★★★☆
 库存上升 9家         深圳 74  ★★★★☆
────────────────
共性主题：18 个代表处提及"海外订单延期"
[建议：机关统一制定专项方案]
```

### 3.4 经营知识中心

**功能清单**

- **经营卡片**（每代表处 × 周期一张）：经营评分、AI 摘要、亮点、风险、重点事项、核心指标、可信度；
- **指标库**：统一指标名称、别名、单位、口径说明，解决各代表处口径不一致；
- **历史沉淀**：所有期次材料解析后自动入库，支持跨年度检索与对比；
- **知识问答**：基于卡片库 + 向量检索回答历史问题。

**典型问答**

- 过去三年哪些代表处利润连续下降？
- 哪些事项三次以上出现？
- 哪些经营问题一直没有解决？
- 北京去年 Q2 的现金流情况？

### 3.5 事项闭环中心

**功能清单**

- 事项抽取：从材料中抽取事项、责任人、截止时间、来源页码；
- 人工确认：AI 抽取结果经人工确认后才进入事项池（避免噪声污染）；
- 跨期匹配：同一事项跨季度自动关联（相似度 + 规则），识别"延期/连续出现"；
- 提醒升级：截止前提醒 → 逾期升级 → 连续 N 期未完成红牌预警；
- 闭环回写：新一期材料提及完成时，建议将事项置为已完成（人工确认）。

**页面示意**

```
事项池
事项            负责人   截止      状态       来源      历史
完成渠道整改      张三    09-30    延期↑      Q1-P18    Q1→Q2→Q3
库存清理方案      李四    08-15    进行中      Q2-P22    Q2
海外订单交付      王五    07-31    已完成 ✓    Q1-P12    Q1→Q2
────────────────
⚠ 连续三个季度未完成：渠道整改（Q1/Q2/Q3）
```

## 4. AI 能力与流水线设计

### 4.1 三级 AI

| 层级               | 定位     | 输出                       |
| ------------------ | -------- | -------------------------- |
| AI Review（预审）  | 效率工具 | 问题清单、可信度           |
| AI Analyst（分析） | 经营助手 | 评分、画像、排行、共性主题 |
| AI Copilot（问答） | 领导助手 | 带来源的自然语言回答       |

### 4.2 解析流水线（Material Parse Agent）

```
Stage 1  File Loader      上传/URL → 本地文件          （Python，无 LLM）
Stage 2  Document Parser  文件 → Document Tree         （python-pptx / pdfplumber / python-docx）
Stage 3  Page Renderer    文档 → 每页 PNG              （LibreOffice CLI）
Stage 4  OCR              图片 → 文字                  （RapidOCR，可换）
Stage 5  Vision           图表/SmartArt/流程图 → JSON  （视觉模型，可选 GPT/Claude/Qwen-VL）
Stage 6  Business         页面分类 / 实体 / 指标 / 事项 / 问题（4 个 Skill，全部 JSON）
Stage 7  IR Builder       Merge + Normalize + Validate → Business IR（Python，无 LLM）
```

平台层（阶段 1+ 追加）：

```
Stage 8  Review Engine    IR + 规则库 + 外围数据 → Findings
Stage 9  Insight Engine   评分 / 排行 / 雷达 / 共性聚类
Stage 10 Card Builder     IR + 洞察 → 经营卡片
Stage 11 Action Tracker   事项匹配历史、状态流转、提醒
```

### 4.3 Skill 规范

目录结构（每个 Skill 独立目录，禁止 Prompt 写进代码）：

```
skills/
├── vision/                 # 图表、SmartArt、流程图理解
├── slide_classifier/       # 页面分类：Summary/Revenue/Risk/Forecast/Action
├── entity_extractor/       # 指标/组织/人员/时间/问题
├── schema_extractor/       # Risk / Finding / Todo / Forecast
├── relationship_builder/   # 指标→原因→发现 关系构建
├── finding_checker/        # 预审问题判定（LLM 兜底部分）
├── action_extractor/       # 事项、责任人、截止时间抽取
└── qa/                     # Copilot 问答链路
```

每个 Skill 包含：`skill.md`（职责）、`prompt.md`、`output_schema.json`。

### 4.4 校验规则引擎（预审规则库，全部可配置）

**完整性**

- R-C01 必选章节覆盖：经营概况、收入、利润、现金流、费用、库存、风险、下一步计划；
- R-C02 必填指标：收入、利润、现金流；
- R-C03 期间标识：材料必须标注本期（如 2026Q2）；
- R-C04 页数异常：低于阈值（如 15 页）提示；
- R-C05 附件缺失：正文提到附件但未提供。

**可信性**

- R-T01 同比复算：`本期值 / 上年同期 - 1` 与声称增速偏差 > 0.5pct 即报；
- R-T02 环比复算：同上；
- R-T03 增长率口径一致：同一指标在不同页声称的增速一致；
- R-T04 引用一致：正文、图表、备注之间数值一致；
- R-T05 外围数据比对：与预算、财报、上期材料比对；
- R-T06 单位量纲归一：亿元/万元混用检测。

**合理性**

- R-R01 异常波动：|环比| > 30% 或 |同比| > 50% 且无解释 → 高等级；
- R-R02 行业规律：毛利率、费用率偏离合理区间；
- R-R03 矛盾检测：文字结论与数据方向相反；
- R-R04 风险信号：现金流为负、库存/应收激增；
- R-R05 目标达成：达成率 < 60% 或 > 150%。

**一致性**

- R-S01 单页内：标题与表格数字一致；
- R-S02 跨页：同一指标不同页数值一致；
- R-S03 跨 PPT：同一代表处本期与上期口径一致；
- R-S04 跨期间：本期实际与上期"预测本期"吻合；
- R-S05 跨代表处：同类指标口径、单位、币种一致。

### 4.5 经营评分模型（必须可解释）

```
综合评分 = 财务表现分 × 60% + 材料质量分 × 20% + (100 - 风险暴露分) × 20%

财务表现分 = 收入增长 × 30% + 利润增长 × 30% + 目标达成 × 25% + 现金流健康 × 15%
风险暴露分 = 重大问题×10 + 高×5 + 中×2 + 低×0.5（上限 100）
```

- 评分必须输出"评分说明"：哪些指标贡献、哪些问题扣分、数据来源页；
- 评分只用于排序与关注分级，不替代人工判断；
- 权重与阈值可在后台配置。

### 4.6 事项匹配与跟踪

- 抽取：LLM 从 IR 中提取（事项/责任人/截止时间/来源页码），置信度低转人工；
- 匹配：同一代表处 + 事项文本向量相似度 ≥ 0.85 + 责任人一致 → 判定为同一事项；
- 状态机：`待办 → 进行中 → 已完成 / 逾期 / 取消`；
- 提醒：截止前 7 天提醒；逾期自动升级；连续 3 期未完成 → 红牌预警。

### 4.7 Copilot 问答链路

- 意图分类：指标查询 / 对比 / 趋势 / 事项跟踪 / 原因分析 / 共性主题；
- 工具路由：指标 SQL 查询、卡片向量检索、事项库查询、聚类结果查询；
- 回答格式：**结论 + 数据 + 来源**（材料、页码、指标 ID、卡片 ID）；
- 兜底规则：数据不足时明确说明缺口，禁止无来源编造。

### 阶段 4：经营知识中心 + AI Copilot（4–6 周）

- 交付：经营卡片库、指标口径库、向量检索、自然语言问答；

## 9. 风险与对策

| 风险                       | 影响             | 对策                                                         |
| -------------------------- | ---------------- | ------------------------------------------------------------ |
| PPT 版式多样导致解析不稳定 | 指标漏抽、错抽   | 确定性提取 + 视觉理解分级；每份材料输出置信度；低置信度转人工 |
| LLM 幻觉导致误报/错判      | 领导被误导       | 校验规则优先；LLM 只做理解；所有结论带证据引用；人工确认闭环 |
| 指标口径不统一             | 跨代表处对比失真 | 指标库统一口径、单位归一；跨代表处一致性提示                 |
| 事项抽取噪声               | 事项池污染       | 抽取后必须人工确认才入库；相似度匹配设阈值                   |
| 经营数据敏感               | 合规风险         | 私有化部署、数据不出域、RBAC 权限、操作审计                  |
| 解析成本高（多模态）       | 费用与排队       | 模型路由（简单页用小模型）、结果缓存、批量并发复用           |

## 10. 总体验收标准

1. 全流程跑通：材料 → IR → 预审 → 卡片 → 洞察 → 事项 → 问答；
2. Business IR 字段完整率 100%（Schema 校验通过）；
3. 所有 AI 输出可溯源到具体材料与页码；
4. 每个解析任务有完整 Workflow Trace；
5. 问题与事项支持人工确认/纠错，纠错结果可回流。
